# インターネットの起源:ARPANET
- ARPANET
  - 1960年代
  - コンピュータ同士を結ぶ研究を始めた
  - ARPAが中心

- ポイント
  - インターネット=通信基盤
  - WWW(Wev)=その上のサービス
- パケット交換方式
      - 大きなデータをいきなり送ると途中で失われると再建できなくなる
      - 小さく分割して送って宛先で復元
      - 復元するための情報=ヘッダ
      - 回線は一つでもいくつかの通信を並行して送れる
      - 
- 分散型ネットワーク
      - 故障時に迂回でくる仕組み
      - 故障した地点があった場合
        - 一本の道だと通信できなくなる
        - 迂回路があったらそっちを使える
- TCP/IP
  - 1980年代ARPANET以外のネットワークが増加
  - 同じ送信ルールでないと通信ができない
  - 共通のルールを採用し複数のネットワークを相互接続した
  - 通信プロトコル=コンピュータ間でデータをやり取りするための取り決め
- 研究から一般へ
  - 1990年だい
    - ISPが登場
      - ネットワークに繋いでくれるプロバイダー
      - 民間で登場
      - 一般でも接続できるようになった
  - 1995年
    - Windows95が普及
    - 個人の利用が拡大
- 日本のインターネット
  - 1984年: JUNET 
    - 大学・研究機関をつなぐ
  - 1988年: WIDE
    - TCP/IPによる広域ネットワークを構築
  - 1992年: IIJ
    - 日本の商用接続の展開
    - 日本初のISP
- WWWの発明
  - 1989:CEERNのティム・バーナーズ・リーが提案
    - 課題
      - 研究者が各地の資料を参照・共有しにくいい
      - 文章の関連情報を探しづらい
    - 着想
      - 文書と文書をリンクで結ぶハイパーリンクが登場
- WEBを動かす4つの要素
  - URL
    - 文書の場所を表すアドレス
  - HTML
    - 文書やリンクを記述する言語
  - HTTP
    - 文書をやり取りする通信ルール
  - サーバ・ブラウザ
    - 文書を送る側、閲覧する側
- 公開と標準化がWebを広げた
  - 無料で公開
    - 技術・プログラムを誰もが利用できるようにした
    - 個人・企業・団体がWebページを作り他のページへリンクできる
    - 情報発信、商業活動の参加者が広まった
  - W3C
    - Web技術の発展と標準化を進める組織
- Mosaicが画像と文字を一緒に表示
  - 1993年
  - HTMLがベース
  - 文字と画像をレイアウトとして、一つのページに表示
  - ブラウザで見える表現の幅が広がる
- ブラウザ競争と表現の拡張
  - Netscape Navigator
    - 昨日限定版の無料配布
  - Internet Explorer
    - 機能競争が「ブラウザ競争」へ
  - プラグイン
    - 音声・動画・アニメーションなどを表現
  - Netscapeのコードの公開は、Firefoxにつながる
  - IEはedgeにつながる
  - ブラウザの規格・機能は
    - HTMLのプログラムをレンダリングして、画像なり文字なりにして表示
    - 読み取り方に差があるのが課題
    - HTMLを書いてもブラウザによって表示が変わってしまう
- 標準技術とブラウザの変化
  - HTML5
    - 2014年
    - 音声・動画・アニメーションを標準機能へ
- Webページの構成要素
  - HTML
    - 文章の構造
    - タグで文書の役割を示す
      - 見出し
        ```
        <h1>こんにちは</h1>
        ``` 
      - 段落
        ```
        <p>よろしくお願いします</p>
        ``` 
  - CSS
    - 見た目
      - 同じHTMLでもCSSが異なると見せ方を変えることができる
      - 役割分担が大事 
  - JavaSciript
    - 操作に応じた動き・機能
      - 動的な要素の役割
  
    ```mermaid
        graph TD;
         利用者の操作　---> JavaScirpt
         JavaScirpt ---> 表示や動きが変わる
    ```
      - 例
        - メニューを開く・画像を切り替える
        - jQueryなどのライブライりにまとまってる
    - カルーセル
- 画像・音声・動画を選んで使う
  - JPEG:写真など
  - PNG:透過など
  - GIF:短いアニメーションを扱える
  - SVG:拡大しても鮮明な図形など
# Webサーバとクライアント
- Webページを保存・公開するコンピュータ
  - Webサーバ：Webサイトのファイルを保管し、公開する
  - クライアント:Webブラウザからページを閲覧する側
    - ブラウザがURLを指定すると、サーバとの通信が始まる
- URLを指定して、DNSで接続先を探す
  - 例 https://www.takushoku-u.ac.jp
  - URL　Webページの場所をブラウザに示す
  - DNSドメイン名をIPアドレスに変換する
  
    ```mermaid
        graph TD;
        クライアント-- takushoku-u.ac.jp-->DNS 
        DNS-- IPアドレス-->サーバ 
    ```
- FQDN
  - ホスト名とドメイン名で構成されている
    ```
    www.takushoku-u.ac.jp
      |    |        |  |
      |    |        |  |-トップレベルドメイン
      |    |        |-----サブレベルドメイン
      |    |--------------サードレベルドメイン   
      |-------------------ホスト名
    ```  
- HTTP
    - ブラウザが要求しサーバがデータを返す
    ```mermaid
        graph TD;
            Webブラウザ--HTML-->クライアント
            クライアント--URL-->Webブラウザ
    ```

  - ポータルサイトと呼ばれる
  - 分類された入口
    - カテゴリを選び、目的のサイトへ

  - リンク先とページ内のキーワードを集めて、検索を備える
  - クローラー
    - Webのリンクを辿るプログラム
  - 収集
    - ページのキーワードやURLを取得
  - データベース
    - 集めた情報蓄積
  - 課題
    - 検索語の数だけでは欲しい情報に近づきにくい
    - 検索語を多く含むページが上位になりやすい
  - PageRank
    - リンク数と、リンク元の表がを手がかりにする
  - 検索結果
    - 重要度の高いページを見つけやすくする
- Amazon
  - 1995年オンライン書店として始まった
  - 買い物かご、などが特徴だった
  - ECの機能を広げた
    - 買い物かご
    - レコメンド
      - 閲覧履歴などから商品を提案
    - AWS
      - 企業にクラウド基盤を提供
- Facebook  
  - SNSは個人的な関係をネットで表示
- Twitter
  - 短い投稿を共有し、フォロー関係を通じて広げる
  - 投稿　当初は140字程度
  - 拡散　リツイートで他社のツイートをひろまらえた
# Webサイトに種類
- メディア系サイト
  - 新しい記事や特集を、トップページから見つけやすくする
  - カテゴリ
    - 内容の種類から探せる
  - 関連記事
    - 読み終えた後リンクなどをおいておき他のもの案内
  - 広告枠
    - バナーや動画広告を配置
- ECサイト
  - 商品を選び注文、決済を行えるもの
  - 商品をカテゴリでまとまっている
  - 誰と誰が
    - B to B モノタロウとか
    - B to C アマゾンとか
    - C to C メ○カリとか
- 企業サイト
  - 企業理念・会社概要・採用情報などを届ける
  - ユーザの種類によって分類
  - 掲載される情報の例
    - 企業理念
    - 広報IR
    - 商品・CSR・採用
    - 各種問い合わせ
- 商品サイト
  - ブランドと商品の魅力を伝える
  - 写真と映像がポイント
  - ランディングページ
    - 入口 検索結果や広告から訪問する
    - 構成　特徴・メリット・利用者の感想を並べる
    - 目標　購入や会員登録などの行動に導く
  - 求める行動をコンバージョンと呼ぶ
- 店舗サイト
  - ネット販売ではなく、実際の店舗に来てもらうためのサイト
- 個人サイト
  - 作家やアーティストなどが個人の情報を公開する
  - 作品、プロフィール、連絡先などを整理する
- CMS更新しやすい仕組みを選ぶ
  - ワードプレスなど
  - CMS コンテンツを管理し、ページを生成する
  - テーマ　用意されたデザインを利用
  - カスタマイズ　目的に合わせて表示する
# Webページの制作フロー
- プランニング
  - 目的と利用者を定める
    - 目的・役割　サイトが利用者に果たす役割
    - ターゲット　誰が、どのように使うかを検討する
- 設計
  - 情報をどう見せてどう移動するか
    - 全体構造　ページの分類
    - ナビゲーション　利用者が上へ進む道筋を設計
    - ワイヤーフレーム　ページのレイアウトと機能を整理
- 制作
  - 01 掲載する文章や画像動画などの素材を制作・編集する
  - 02 ページの見た目をデザイン
  - 03 HTML・CSSでページを記述する
  - 04 必要な動きや機能をプログラムし、動作を確認する
  - 公開前にテストし、不具合を修正します
    - テストサイトでテストし大丈夫なら公開サイトで公開
- 運用
  - 評価　設計した指標をもとに利用情報を見る
  - 更新　内容を定期的に見直す
  - 改善　デザインや機能を追加・改良する
